- (decision) Slug inherited from upstream brainstorm folder: surf-led-expat-property-platform
- (decision) Property-centric is the locked direction: we are selling property; surf data is a differentiating layer, not the product. Aspirational property visual language wins over Surfline's dark utilitarian aesthetic
- (decision) Discovery is destination-first (country/island) rather than street/postcode-first, matching how this buyer actually chooses
- (constraint) Stack fixed by user: Vite + React 19 + TypeScript + Tailwind + React Router + TanStack Query; Vitest + React Testing Library for tests
- (constraint) No backend and no persistence available - all data ships as static JSON bundled with the app
- (constraint) All data access must sit behind a repository interface so a REST/GraphQL source can replace JSON without touching UI components
- (constraint) Runs locally only - no Docker, no internet-facing deployment (machine-level constraint from C:/Workspaces/CLAUDE.md)
- (decision) Three destinations seeded: Bali, Ko Samui, Mentawai Islands - chosen for seasonal contrast and remote/boat-access flavour
- (decision) Seed data is researched-realistic: real market prices/locations/attributes researched, listing copy written original, imagery from licensed free sources. Rejected verbatim scraping (copyright/ToS) and fully synthetic (fails client scrutiny)
- (insight) Surfline splits into a static Spot Atlas layer and a live Forecast layer; adopting that same seam makes the PoC-now/API-later constraint deliberate architecture rather than scaffolding
- (insight) Ko Samui's surf season (Nov-Apr) is the inverse of Bali's (Apr-Oct), so the 12-month seasonality overlay is a genuine cross-destination decision tool, not decoration
- (insight) Tenure is the expat deal-breaker attribute and differs fundamentally by country (Indonesia Hak Pakai is tied to visa status; Thai lease auto-renewal clauses are unenforceable; Thai condos allow true freehold inside a 49% quota). It belongs on the listing card, not in a FAQ
- (capability) CAP-1 Destination-first discovery: browse/compare destinations as primary surface, property grid within
- (capability) CAP-2 Property search with destination-led filters plus surf attributes, and a location-free surf-first query returning ranked destinations
- (capability) CAP-3 Property listing detail page, aspirational hero-led, carrying the surf intelligence panel
- (capability) CAP-4 Surf breaks as first-class entities with pages, bidirectionally linked to properties
- (capability) CAP-5 Twelve-month seasonality overlay charting swell vs weather vs crowd
- (capability) CAP-6 Surfer profile match score re-ranking destinations and properties against ability, board and crowd tolerance
- (capability) CAP-7 Pluggable data layer - repository interface with a JSON adapter, provably swappable
- (capability) CAP-8 Tenure transparency - ownership structure surfaced as a first-class, filterable listing attribute with plain-English risk notes
